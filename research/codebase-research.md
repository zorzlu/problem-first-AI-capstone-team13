## High-Level Summary
This repository implements a full-stack news briefing system built around three separate LangGraph pipelines. Iteration 1 processes direct company news, Iteration 2 adds catalyst memory and duplicate/update handling, and Iteration 3 adds exposure-graph-based cross-impact routing for untickered events. The backend uses FastAPI for API delivery, local JSON persistence for watchlist and graph state, and in-memory storage for the catalyst ledger and per-ticker expansion status. LLMs are used for canonical event extraction, per-ticker synthesis, an output safety judge, and exposure-graph expansion, while catalyst deduplication uses local embeddings with a deterministic lexical fallback. Per-ticker synthesis and judging are dispatched through LangGraph `Send(...)` worker branches and collected before the compliance gate. The frontend is a single React application that drives watchlist edits, iteration selection, pipeline execution, graph expansion, guardrail-status display, and status inspection through `/api/*` endpoints.

### LLM and Embedding Flows

#### Canonical Event Extraction LLM
- Input data: the article list returned by ingestion, the iteration-specific focus block, and the shared extraction system prompt. Iteration 1 and 2 use direct-news focus over the watchlist; Iteration 3 adds expansion tickers and cross-impact themes derived from the graph. See [D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py:345-575](D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py) and [D:\git\problem-first-AI-capstone-team13\backend\iterations\iter3.py:1-60](D:\git\problem-first-AI-capstone-team13\backend\iterations\iter3.py).
- Model behavior: `get_extraction_llm()` resolves the extraction route from `backend/llm.py`, with Gemini `gemini-2.5-flash-lite` as the default primary model and OpenAI `gpt-4.1-nano` as the default fallback. Per-step environment overrides can route extraction to OpenAI, Gemini, Anthropic, OpenAI-compatible, or local OpenAI-compatible providers. The call uses `.with_structured_output(ExtractionResult)`. The model outputs one `CanonicalEventOut` per qualifying article with event type, summary, hard facts, entities, tags, regions, sectors, commodities, technology themes, directional pressure, uncertainty notes, and evidence strings. See [D:\git\problem-first-AI-capstone-team13\backend\llm.py](D:\git\problem-first-AI-capstone-team13\backend\llm.py) and [D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py](D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py).
- Output data: `canonical_events`, which are later routed into ticker buckets. In no-key mode, the shared module uses its canned `MOCK_EVENTS` dataset and rules-based event assembly instead of calling a live LLM. See [D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py:193-343](D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py).

#### Synthesis LLM
- Input data: `build_ticker_buckets_for_synthesis()` creates ticker-specific buckets from direct events, cross-impact events, and restoration of ledger-backed story threads, then `dispatch_ticker_synthesis()` sends one worker branch per ticker with `active_synthesis_ticker` and `active_synthesis_bucket`. Each worker annotates events with `minutesAgo`, and each hard fact is also stamped with a recency value before synthesis. See [D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py:877-1130](D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py).
- Model behavior: `get_synthesis_llm()` resolves the synthesis route from `backend/llm.py`, with Gemini `gemini-2.5-flash-lite` as the default primary model and OpenAI `gpt-4o-mini` as the default fallback. Each worker call uses `.with_structured_output(SynthesisOut)`. The prompt instructs the model to summarize the net catalyst situation, populate `mainCatalysts`, assign directional pressure and confidence, and keep the output grounded in the bucket context. See [D:\git\problem-first-AI-capstone-team13\backend\llm.py](D:\git\problem-first-AI-capstone-team13\backend\llm.py) and [D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py](D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py).
- Output data: each worker returns one `ticker_synthesis_results` reducer item with the ticker, a per-ticker `TickerSummary` candidate, and L3 counts. `collect_ticker_syntheses()` fan-ins those results into `ticker_syntheses` before the compliance gate. Non-empty LLM candidates are passed to the output safety judge inside the same worker before being returned. In no-key mode, the worker produces a rules-based mock synthesis instead of calling the model and marks the judge as skipped in `guardrailMetadata`. See [D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py:1196-1429](D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py).

#### Output Safety Judge LLM
- Input data: the ticker, the annotated ticker bucket used for synthesis, and the generated synthesis candidate with any existing guardrail metadata removed. The judge call runs inside the same `synthesize_one_ticker` worker branch that produced the synthesis. See [D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py:826-848](D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py) and [D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py:1268-1379](D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py).
- Model behavior: `get_judge_llm()` resolves the judge route from `backend/llm.py`, with Gemini `gemini-2.5-flash-lite` as the default primary model and OpenAI `gpt-4o-mini` as the default fallback, then binds `.with_structured_output(OutputSafetyJudgeOut)`. The judge checks three booleans: `groundingPassed`, `advicePassed`, and `pathPassed`. Grounding requires claims to be supported by the bucket, advice rejects trading/action language, and path checking restricts indirect catalyst explanations to the supplied `impactPath` and `reasonForRouting`. See [D:\git\problem-first-AI-capstone-team13\backend\llm.py](D:\git\problem-first-AI-capstone-team13\backend\llm.py) and [D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py](D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py).
- Output data: if the judge passes, the worker returns the synthesis with `guardrailMetadata.judgeStatus = "passed"`. If it fails, synthesis is regenerated once with the judge defects added to the prompt and judged again. If the regenerated output passes, the status is `regenerated_passed`; if it fails again or the judge errors, `build_degraded_synthesis()` returns a suppressed briefing with no `mainCatalysts`, `overallPossibleInfluence = "unclear"`, and `guardrailMetadata.judgeStatus = "degraded"`. The worker returns L3 counts that the fan-in collector aggregates. See [D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py:1268-1429](D:\git\problem-first-AI-capstone-team13\backend\iterations\common.py).

#### Local Embedding Flow
- Input data: incoming event summaries and the hard-fact text associated with an existing ledger entry. The embedding code loads the local `fastembed` model once and embeds summaries and facts in memory. The default model cache is `backend/state/fastembed_cache`, overrideable with `EMBEDDING_CACHE_DIR`, so a successfully downloaded model can be reused offline. See [D:\git\problem-first-AI-capstone-team13\backend\memory.py](D:\git\problem-first-AI-capstone-team13\backend\memory.py).
- Model behavior: the primary path uses semantic cosine similarity over local vectors, and the fallback path uses deterministic lexical cosine, Jaccard, and containment calculations when the embedding model is unavailable. The similarity threshold used for duplicate-thread comparison is 0.75, and the fact-level Jaccard threshold used in fallback logic is 0.6. See [D:\git\problem-first-AI-capstone-team13\backend\memory.py:121-220](D:\git\problem-first-AI-capstone-team13\backend\memory.py).
- Output data: `check_ledger_decision()` returns `new`, `update`, or `duplicate`, plus the catalyst ID and any newly identified facts. `get_memory_status()` exposes the active dedup provider, embedding model/cache, thresholds, entry counts, LLM step routes, and provider availability to the UI.
